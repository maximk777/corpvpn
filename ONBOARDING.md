# Онбординг с нуля (для коллеги)

Цель: с личного Mac открывать корп-хосты (`wiki.corp.example`, `app.corp.example` и т.д.)
так, будто ты в офисной сети. Трафик VPN-клиента выходит с российского IP
арендованного VPS, поэтому корп-шлюз тебя пускает.

Времени ~20 минут, половина — ожидание установки. Только macOS.

---

## Шаг 1. Купи VPS с российским IP

- Любой хостер с локацией в РФ (Timeweb, Ihor, Selectel, aeza…). Хватает
  самого дешёвого: 1 CPU / 1 GB, Ubuntu.
- Нужен **root по ssh** и **российский IPv4**. Ставить на сервере ничего не
  надо — используем его только как ssh-выход.
- Запиши IP, напр. `45.89.66.177`. Проверь: `ssh root@<IP>` пускает.

## Шаг 2. Одна команда на Mac

```sh
git clone git@github.com:maximk777/corpvpn.git
cd corpvpn
./install.sh
```
Go/компилятор **не нужны** — в репозитории лежит готовый бинарь (`dist/corpvpn`,
universal: Intel + Apple Silicon). `install.sh` положит его в PATH, поставит lima
и autossh, поднимет VM, спросит твой VPS, настроит туннель и **проверит, что
egress идёт с РФ-IP и шлюз отвечает**. Твой системный Go/окружение не трогает.
По ходу попросит:
- вписать `SOCKS_HOST=root@<IP>` в `.env` (откроет редактор);
- один раз пароль от VPS (беспарольный ssh);
- корп-логин, пароль и **TOTP** (как достать — ниже).

## Шаг 3. Дальше каждый день

```sh
corpvpn up        # поднять всё (спросит sudo-пароль для маршрутов)
corpvpn status    # к чему подключён
corpvpn down      # погасить всё
```
Проверка: `curl -s -o /dev/null -w '%{http_code}\n' https://wiki.corp.example/` → `200`.

`up` включает watchdog: если VPN отвалится — поднимется сам. `down` его выключает.

## Как достать TOTP-секрет (второй фактор)

`corpvpn creds set` принимает **любое** из: `otpauth://…`, `otpauth-migration://…`
(экспорт Google Authenticator) или голый base32-секрет. Как получить — по приложению:

### Apple Passwords.app
`File → Export → Passwords…` → в CSV есть колонка `otpauth`. Скопируй ссылку
`otpauth://…` целиком.

### Google Authenticator (проще всего)
1. В приложении: `⋮ → Перенести аккаунты (Transfer accounts) → Экспортировать`.
2. Выбери **только** корп-VPN аккаунт (если экспортировать все — тул возьмёт
   похожий на VPN, но лучше не рисковать) → появится **QR-код**.
3. Считай этот QR любым сканером QR (даже камерой Mac/телефона) — получишь строку
   вида `otpauth-migration://offline?data=…`. Её и вставь в `creds set`.

### Microsoft Authenticator
Экспорта секрета **нет** — MS Authenticator не отдаёт seed сторонним. Варианты:
- Если у тебя сохранён исходный QR/секрет при подключении VPN — используй его.
- Иначе **перевыпусти** второй фактор в корп-портале и при добавлении сохрани
  `otpauth://`-ссылку/секрет (можно сразу и в Google Authenticator, и сюда).

### Aegis / 2FAS / Raivo и другие (Android/iOS)
Все они умеют экспорт в открытом виде: экспортни в JSON/текст — там будет
`otpauth://…` или поле `secret` (base32). Бери его.

> Секрет нигде не «палится»: он идёт только в твой login keychain на этом Mac.
> Не вставляй его в онлайн-декодеры — `corpvpn` разбирает `otpauth-migration://`
> локально, ничего никуда не отправляя.

## Если что-то не так

- `up` пишет «шлюз не отвечает» → смени шлюз в `.env`:
  `VPN_GATEWAY=vpn2.corp.example:8443` (есть `vpn`, `vpn2`, `vpn3`).
- Корп-имя не резолвится, хотя должно → проверь, что домен есть в `CORP_DOMAINS`
  в `.env`, и `./host/route-up.sh`. ⚠️ `dig`/`nslookup` корп-имена не покажут
  (игнорируют `/etc/resolver`) — проверяй только `curl`'ом или в браузере.
- Туннель до VPS живой? → `corpvpn status` покажет внешний IP (должен быть IP VPS).
- Что в VPN-туннеле: `limactl shell vpnbox -- sudo tmux attach -t vpn`
  (отцепиться — `Ctrl-B`, затем `d`).

## Безопасность

- Корп-пароль и TOTP-seed — в macOS login keychain (не в файлах). `corpvpn creds rm`
  удалит.
- IP твоего VPS — только в локальном `.env`, в git он не коммитится.
